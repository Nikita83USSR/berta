# BERTA 0.3

**BERTA — Autonomous Local Intelligence**

Локальный AI-агент для управления компьютером, работы с данными, инструментами и пользовательским интерфейсом.

## Версия

**BERTA 0.3**

Текущая версия предназначена для локального запуска на Linux и сохраняет совместимость с существующей архитектурой BERTA 0.2.

---

# 1. Главный файл запуска

## `berta_agent.py` — главный запускаемый файл

Это **основная точка входа BERTA**.

Запускать BERTA следует именно так:

```bash
cd ~/berta_project/berta_0.1_final
python berta_agent.py
```

`berta_agent.py`:

- является главным launcher;
- выводит фирменный ASCII-логотип BERTA;
- подготавливает запуск в `.venv`;
- передаёт управление внутреннему ядру.

### Важно

`main.py` **не является основным пользовательским entry point**.

`main.py` — внутренний модуль ядра, который запускается через `berta_agent.py`.

Не следует менять эту архитектуру без отдельного решения.

# 2. Python environment

Для BERTA используется отдельное виртуальное окружение:

```text
.venv/
```

Рекомендуемая установка:

```bash
cd ~/berta_project/berta_0.1_final

python3 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
pip install piper-tts
```

BERTA должна запускаться из этого окружения либо автоматически использовать проектный `.venv`.

# 3. Голос BERTA

## TTS: Piper

BERTA использует **Piper TTS**.

### Голос

Используемый голос:

```text
ru_RU-irina-medium
```

Файлы модели:

```text
~/.berta/voices/ru_RU-irina-medium.onnx
~/.berta/voices/ru_RU-irina-medium.onnx.json
```

Установка:

```bash
mkdir -p ~/.berta/voices
cd ~/.berta/voices

wget -O ru_RU-irina-medium.onnx \
"https://huggingface.co/rhasspy/piper-voices/resolve/v1.0.0/ru/ru_RU/irina/medium/ru_RU-irina-medium.onnx?download=true"

wget -O ru_RU-irina-medium.onnx.json \
"https://huggingface.co/rhasspy/piper-voices/resolve/v1.0.0/ru/ru_RU/irina/medium/ru_RU-irina-medium.onnx.json?download=true"
```

### Критически важно

Не заменять Piper другой TTS-моделью без отдельного изменения архитектуры.

Не считать GigaChat голосовым движком.

GigaChat и Piper выполняют разные задачи:

```text
GigaChat / нейросетевое ядро
        ↓
формирование ответа
        ↓
Piper TTS
        ↓
ru_RU-irina-medium
        ↓
голос BERTA
```

# 5. Function Calling

BERTA использует инструменты для выполнения реальных действий.

Главное правило:

**результат функции нельзя отправлять в историю отдельно от соответствующего вызова функции.**

Правильная последовательность:

```text
USER
 ↓
ASSISTANT + FUNCTION CALL
 ↓
FUNCTION RESULT
 ↓
ASSISTANT
```

Результаты инструментов должны сериализоваться как настоящий JSON.

Нельзя использовать:

```python
str(result)
```

для передачи результата Function Calling.

Следует использовать JSON-сериализацию:

```python
json.dumps(result, ensure_ascii=False)
```

Это предотвращает ошибки вида:

```text
Invalid params
JSON parse error
```

и:

```text
every assistant function result must have an assistant function call in history
```

# 6. Управление компьютером

BERTA 0.3 содержит отдельный слой управления ПК.

## Принцип

BERTA не должна жёстко предполагать, что конкретная программа установлена.

Например, запрос:

```text
запусти блокнот
```

не должен автоматически превращаться в:

```bash
gedit
```

или:

```bash
mousepad
```

Сначала определяется окружение пользователя и наличие приложений.

---

# 7. Определение рабочего окружения

BERTA должна учитывать:

- Linux distribution;
- Desktop Environment;
- доступные программы;
- наличие команды в `PATH`;
- фактически установленные desktop applications.

Например:

```text
XFCE → Mousepad
GNOME → GNOME Text Editor / gedit
KDE → Kate / KWrite
```

Но конкретная программа выбирается только если она действительно установлена.

Принцип:

```text
Пользовательский смысл
        ↓
локальный resolver
        ↓
реально установленное приложение
        ↓
запуск
```

а не:

```text
Пользовательский смысл
        ↓
жёстко заданная команда
```

---

# 8. Управление приложениями

Используются отдельные функции для:

- определения рабочего окружения;
- получения списка приложений;
- поиска подходящего приложения;
- запуска приложения;
- контроля процессов.

Основной инструмент запуска приложений:

```text
launch_application
```

Приложение выбирается локально на основании реального состояния машины.

---

# 9. Работа с файлами

BERTA может использовать отдельные операции для файловой системы:

```text
list_directory
find_files
read_file
open_path
```

Примеры:

```text
Покажи содержимое Downloads
```

```text
Найди папку berta
```

```text
Найди config.py
```

```text
Открой эту папку
```

Для файловых операций желательно использовать специализированный инструмент вместо произвольной shell-команды.

---

# 10. Процессы и системное управление

BERTA может работать с процессами:

```text
list_processes
terminate_process
```

Также существует общий системный инструмент:

```text
execute_system_command
```

Он является более низкоуровневым инструментом и не должен использоваться там, где существует специализированная функция.

Приоритет:

```text
специализированный инструмент
        ↓
если невозможно — системная команда
```

---

# 11. Фоновые задачи

Фоновые операции должны иметь идентификатор задачи:

```text
task_id
```

и состояние выполнения.

Это позволяет запускать длительные процессы, не блокируя основной интерфейс.

---

# 12. Безопасность

Секреты не должны находиться в исходном коде.

В репозиторий нельзя помещать:

```text
.env
```

реальные API keys, passwords, tokens и credentials.

Использовать:

```text
.env.example
```

как шаблон конфигурации.

Перед публикацией проверять:

```bash
git status
git diff
```

и содержимое `.gitignore`.

---

# 13. Интерфейс

Web UI BERTA не должен раскрывать внутреннюю реализацию нейросетевого провайдера пользователю без необходимости.

В пользовательском интерфейсе используется понятие:

```text
CORE
```

или:

```text
локальное интеллектуальное ядро
```

а не название конкретного API-провайдера.

---

# 14. Голосовой интерфейс

В интерфейсе поддерживается голосовой режим.

Основная цепочка:

```text
BERTA response
      ↓
TTS preparation
      ↓
Piper
      ↓
Irina
      ↓
audio playback
```

Голос должен воспроизводиться без необходимости менять модель или вручную указывать конкретный Linux desktop.

---

# 15. Совместимость

BERTA должна ориентироваться на фактическое окружение машины.

Не следует предполагать:

```text
XFCE
GNOME
KDE
```

заранее.

Не следует предполагать наличие:

```text
gedit
mousepad
kate
```

заранее.

Сначала обнаружение, затем выбор.

# 16. Правило дальнейшей разработки

При дальнейших изменениях необходимо сохранять следующие инварианты:

### Entry point

```text
berta_agent.py
```

### Internal core

```text
main.py
```

### TTS

```text
Piper TTS
```

### Voice

```text
ru_RU-irina-medium
```

### Voice location

```text
~/.berta/voices/
```

### Python environment

```text
.venv
```

### Main launcher

```bash
python berta_agent.py
```

### Provider abstraction

Конкретный нейросетевой провайдер является частью backend/core и не должен смешиваться с TTS.

### PC control

Управление ПК должно быть адаптивным к фактической системе пользователя.
